# notifications

**MVP** — owns `Notification`, `NotificationPreference` (see `prisma/schema/notifications.prisma`), per File 11 Part 03. The backend dispatches transactional, informational, and explicitly listed safety-critical event templates through the transactional outbox; clinical escalation policy and a real SMS provider are still open decisions.

**Google Cloud credentials (2026-09-30):** Cloud Run should set
`FIREBASE_PROJECT_ID` and use its attached service identity through Firebase
Admin SDK Application Default Credentials (ADC). Grant that runtime identity
the needed FCM send permission in the Firebase project; do not create or store
a service-account private key for Cloud Run. The optional
`FIREBASE_CLIENT_EMAIL`/`FIREBASE_PRIVATE_KEY` pair remains for non-Google
hosts and should be held in a secret manager. A partial pair is rejected.

**2026-09-29 reliability and privacy pass.** An outbox event ID makes notification-row creation idempotent per recipient/channel. Multi-channel events keep one visible inbox card; SMS has its own hidden delivery row. Push delivery is claimed under a 10-minute lease and consumes one bounded attempt at claim time, including a worker crash after a possible provider handoff. Transient FCM failures alone are retried; invalid-token pruning uses the exact owner, session, device ID, and registration version captured for that send, so a delayed response cannot remove a newer registration. An expired lease at the attempt limit becomes terminal `FAILED`. This is at-least-once external handoff: a crash after provider acceptance but before `SENT` can still result in a duplicate push on retry; FCM does not provide an exactly-once guarantee here. Android tray pushes carry the stable inbox notification ID as the notification tag, so a retry replaces the same tray item rather than adding another copy; separate notification rows remain separate alerts. `SENT` means accepted by FCM, not displayed or read on a device. Outbox worker claims also consume a bounded attempt; stale exhausted claims become `FAILED`, while missing-handler rows remain `SKIPPED` without burning budget. Notification and outbox outcome writes are fenced against stale workers. Every lock-screen/tray push has generic Arabic copy; only `templateCode`, tier, notification ID, and opaque route IDs are sent as FCM data. Clinical, financial, pharmacy, and staff details stay in the authenticated inbox. A missing SMS provider fails closed as `FAILED` with no false `SENT` row and no patient phone or clinical text in logs. Real FCM/APNs/web delivery and SMS remain unverified.

`POST /v1/auth/devices` now binds a globally unique FCM token to its current owner and live login session. `DELETE /v1/auth/devices/current` removes `{fcmToken}` for the bearer account (204); `POST /v1/auth/logout` accepts optional `fcmToken` as a legacy cleanup fallback and removes devices registered to the ended session. Do not send a token or clinical text in a URL. The browser/mobile clients must register only after login, unregister before clearing credentials, and refresh registration when FCM rotates the token.

Pharmacy `OUT_FOR_DELIVERY` text uses the persisted `fulfillment_type`: home delivery and clinic handover are distinct. The push does not claim a courier position, ETA, or physical receipt. Clinic handover staff fan-out is based on a verified appointment's saved clinic branch and active branch-scoped assistants; see `pharmacy-fulfillment/README.md`.
